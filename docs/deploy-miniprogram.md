# 发布课表小程序

小程序是可选的。网页和日历订阅完全独立可用，不发小程序也不影响。

发小程序的好处只有一个：同学在微信里点一下就能看，不用翻聊天记录找链接。

---

## 一、先想清楚要不要发

| | 网页 | 小程序 |
|---|---|---|
| 成本 | 几乎为零 | 要注册账号、配域名、走审核 |
| 更新 | 改完传上去就行 | 改数据不用审核，改功能要审核 |
| 入口 | 分享链接 / 加到桌面 | 微信里搜、扫码、聊天分享 |
| 门槛 | 无 | 需要已备案的 HTTPS 域名 |

结论：先把网页做好用起来，小程序有余力再做。

---

## 二、准备工作

### 1. 注册账号

到 [mp.weixin.qq.com](https://mp.weixin.qq.com) 注册小程序，个人主体即可。

拿到 **AppID**：后台「开发管理 - 开发设置 - 开发者 ID」。

### 2. 选服务类目

建议选「工具 - 信息查询」。

**不要选教育相关类目**，会被要求提供办学许可证之类的资质，个人主体拿不出来。

### 3. 配 request 合法域名

后台「开发管理 - 开发设置 - 服务器域名 - request 合法域名」，填你放 `schedule.json` 的域名。

三个硬性要求：

- 必须是**域名**，不能填 IP
- 必须是 **HTTPS**
- 服务器在国内的，域名必须**已 ICP 备案**

**这一步通常是整个流程里最花时间的，建议最先办。** 域名没配好之前，小程序会静默回退到包内内置数据，不会报错，但也拉不到更新。

### 4. 装开发者工具

[微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html),装在一台有图形界面的电脑上。

---

## 三、构建与导入

```bash
# config.json 里填好这两项
#   "miniprogram": { "appid": "wx..." }
#   "site": { "baseUrl": "https://你的域名" }

npm run build
```

构建会自动生成：

- `miniprogram/data/schedule.js` — 包内内置的兜底数据
- `miniprogram/config.js` — 远程数据地址、班级名、CalDAV 配置
- `miniprogram/theme.wxss` — 主题配色
- 顺带把 `project.config.json` 里的 AppID 和 `app.json` 里的导航栏标题一并填好

然后在开发者工具里「导入项目」，目录选 `miniprogram/`。

---

## 四、发布

### 体验版（日常用这个）

1. 开发者工具右上角点「上传」，填版本号和备注
2. 到后台「版本管理 - 开发版本」，找到刚上传的那条
3. 点「选为体验版」
4. 把体验版二维码发给同学

体验版不需要审核，上传完几分钟就能用，**日常用这个就够了**。

### 正式版

1. 后台「版本管理 - 开发版本」点「提交审核」
2. 填功能页面、标签、测试账号（没有登录功能就写「无需登录」）
3. 审核一般 1 到 3 个工作日
4. 通过后点「发布」

课表类小程序内容简单，一般不会被拒。被拒最常见的原因是类目选错、或者服务器域名没配。

## 五、日常更新

**改课表不需要重新提审。**

```bash
# 1. 改 data/schedule.json，记得改 version
# 2. 重新构建
npm run build
# 3. 只需要把 site/dist/schedule.json 传到服务器
```

小程序每次启动会去拉远程 `schedule.json`，发现 `version` 变了就更新界面并写入本地缓存。

需要重新上传并提审的只有：改了页面结构、样式、交互逻辑。

### 数据加载策略

小程序的数据加载是三层兜底，顺序是：

1. **本地缓存** — 秒开，断网也能看
2. **包内内置数据** — 首次安装、缓存被清时用
3. **远程 `schedule.json`** — 后台静默拉取，拿到新版本就刷新界面

所以即使服务器挂了、域名没配好，小程序也不会白屏，只是看到的是打包时的那份数据。

## 六、常见问题

| 现象 | 原因 |
|---|---|
| 小程序显示的还是旧课表 | `version` 没改；或者域名没加进 request 白名单；或者 CDN 缓存没过期 |
| 开发者工具报「不在合法域名列表中」 | 域名没配，或者配完没点「保存并提交」 |
| 真机预览正常，体验版拉不到数据 | 开发者工具默认勾了「不校验合法域名」，真机不会。回去检查白名单 |
| 导入项目报 AppID 无效 | `config.json` 里 `miniprogram.appid` 没填，重新 `npm run build` |
| 页面顶部被胶囊按钮遮住 | 这个框架用的是自定义导航栏，已经做了安全区适配。如果还有问题，检查 `utils/navbar.js` |

---

## 七、要不要做多个班共用

一个小程序服务多个班，技术上只要让 `schedule.json` 按班级分文件、启动时让用户选一次就行。

但这会引入「用户状态」，需要考虑切换、记忆、默认值。框架没做这个，**一个班一个小程序更省事**，反正注册是免费的。
