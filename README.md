# 课表三件套开源框架

把你的班级课表变成三样东西：**一个手机上好用的课表网页**、**一份可以订阅到系统日历的日程**、**一个可以提审发布的微信小程序**。

三样东西共用**同一份 JSON 数据**。改课、调课、换教室，只改那一个文件，跑一条命令，三边同时更新。

> 这套东西最初是给北京大学光华管理学院某个 MBA 班级做的，现在把功能框架抽出来开源。仓库里**不包含任何真实课程、老师、讲义数据**，自带的示例数据全部是虚构的。视觉上保留了光华红 + 暖金的配色和排版骨架，配色和文案都可以在配置里改掉。

## 先看看长什么样

```bash
git clone https://github.com/chacesclaw/guanghua2026.git
cd guanghua2026
npm run demo      # 用自带的虚构示例数据构建
npm run serve     # 打开 http://localhost:8080
```

不需要装任何依赖，`node_modules` 是空的，只要 Node 18 以上。

## 一、你需要提前准备什么

先把这一节读完再动手。大部分人卡住不是卡在代码上，是卡在没准备域名或者没搞清楚小程序要什么。

### 1. 小程序需要准备什么

| 项目 | 说明 | 卡点 |
|---|---|---|
| 微信小程序账号 | 到 [mp.weixin.qq.com](https://mp.weixin.qq.com) 注册，拿到 **AppID** | 个人主体就可以，不需要企业 |
| 服务类目 | 建议选「工具 - 信息查询」 | 别选教育类，会被要求提供办学资质 |
| 微信开发者工具 | 装在一台有图形界面的电脑上，用来上传代码 | 命令行 CLI 也可以，但仍需先在图形界面里登录一次 |
| request 合法域名 | 后台「开发管理 - 开发设置」里填一个 HTTPS 域名 | **必须是域名，不能填 IP；国内服务器要求已备案** |

小程序**不需要后端**。它只做一件事：去你的 HTTPS 地址拉一份 `schedule.json`。所以**改课表不需要重新提审小程序**，这是这套架构最省事的地方。

不想发小程序？跳过即可，网页和日历订阅完全独立可用。

### 2. 网站需要准备什么

| 项目 | 说明 |
|---|---|
| 静态托管 | 产物只有 HTML / JSON / 图片。Cloudflare Pages、Vercel、GitHub Pages、对象存储、自己的 nginx 都行 |
| HTTPS | **必须**。小程序和日历订阅都不接受 http |
| 图标 | 不放自己的图标时，构建会自动生成纯色占位图标，不会报错 |

国内访问 GitHub Pages 时通时不通，给国内同学用建议走 Cloudflare 或国内对象存储。

### 3. 日历订阅需要准备什么

有两条路，先看清楚区别再选，别一上来就去搭服务器，也别默认 ICS 就够。

| 方案 | 需要准备 | 系统自带日历支持度 |
|---|---|---|
| **A. CalDAV（推荐）** | 一台服务器跑 [Radicale](https://radicale.org/) 或 [Baïkal](https://sabre.io/baikal/)，外加一个**只读账号** | **几乎全平台原生支持**：iOS、macOS、Android、鸿蒙、Windows |
| **B. ICS 订阅（零成本）** | 只要一个 HTTPS 静态地址放 `calendar.ics`，**不需要任何服务器** | iOS、macOS、Outlook 可以；**安卓和鸿蒙自带日历大多不支持** |

**怎么选：** 班里有安卓或鸿蒙同学（也就是绝大多数班级）就用 CalDAV，这是唯一能让全班都用系统自带日历、不装任何 App 的方案。手上没服务器、想先零成本跑起来，就用 ICS，苹果用户体验一样好。两个可以同时开。

必须知道的三件事：

- **CalDAV 给同学的账号必须在服务端关掉写入权限。** 它本身是可读写协议，不关的话任何一个同学误删一节课都会同步回服务器，全班跟着错。
- **CalDAV 的账号密码会出现在公开网页的源码里。** 所以那个账号只能是只读、专用、可随时作废的。不想印在页面上的话，密码留空即可，网页会显示「请向课代表索取」。
- **订阅类日历都不是实时的。** 各平台按自己的节奏拉取，Google 日历最长可能到 24 小时，`REFRESH-INTERVAL` 只是建议不是命令。改了课表，别指望同学手机立刻变。

详见 [`docs/caldav.md`](docs/caldav.md)。

### 4. 服务器需要准备什么

**网页和小程序：什么都不需要。** 这两个产物全是静态文件，没有后端进程、没有定时任务。

想用自己的机器托管，nginx 加 [Cloudflare Tunnel](https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/) 就够，连公网 IP 都不用有。

**只有 CalDAV 需要一台常驻服务器**（跑 Radicale 或 Baïkal）。选 ICS 订阅方案的话，同样什么都不需要。

### 5. 域名需要准备什么

| 项目 | 说明 |
|---|---|
| 一个域名 + DNS 管理权 | 二级域名就够，比如 `schedule.你的域名` |
| 备案 | 服务器在国内必须 ICP 备案。走 Cloudflare + 境外源站可以绕开，代价是国内速度不稳 |
| 同源 | 网页、`schedule.json`、`calendar.ics` 放同一个域名下，省掉跨域和白名单的麻烦 |

小程序那条 request 合法域名的要求最硬：**必须是域名，而且国内服务器必须已备案**。这一条往往是整个流程里最花时间的，建议最先办。

### 6. 数据库需要准备什么

**不需要，这是刻意的设计。**

整套系统的数据源就是一个 `schedule.json`。不用数据库换来的好处：没有运维、没有备份、没有账号密码、改动走 git 天然有版本记录、任何 AI Agent 都能直接读写。

只有当你想加「每人不同的状态」（个人打卡、自定义提醒、选课差异化）时才需要数据库。框架在数据契约里留了扩展位，但不含实现。

### 7. 课表需要准备什么

这是唯一真正需要你投入时间的部分。

- **原始素材**：教务发的 Excel、PDF、邮件、微信 / 钉钉通知，甚至截图都行，Agent 能读。
- **需要能整理出的字段**：日期、时间段、课程名、授课老师、教室、课程性质（必修 / 选修）、学分、面向班级、备注。
- **另外需要的**：学期起止日、调休和节假日、临时调课通知。
- **人工校对**:Agent 从 PDF 或截图里提取一定会出错，**上线前必须逐条对一遍**，尤其是时间和教室。`npm run build` 会自动检查时间冲突、缺教室、分类未定义这些低级错误，但它查不出「9:00 被抄成 19:00」这种错。

### 8. 其他需要准备的

- **一个 AI Agent**：能读写文件、能执行命令的那种（Claude Code、Cursor 之类）。手工填 JSON 也行，就是慢。
- **视觉素材**：你自己有权使用的院徽 / 班徽。仓库**不附带任何学校标识图片**，只保留配色和排版骨架。
- **一个负责人**：说清楚谁改数据、谁发布。多人同时改一个 JSON 会冲突。
- **时区**：默认 `Asia/Shanghai`，在 `config.json` 里改。

## 二、五分钟跑起来

```bash
# 1. 拿到代码
git clone https://github.com/chacesclaw/guanghua2026.git
cd guanghua2026

# 2. 建自己的配置（config.json 已在 .gitignore 里，不会被提交）
cp config.example.json config.json

# 3. 改 config.json：至少把 class.name 和 site.baseUrl 填上

# 4. 把示例数据复制一份当起点
cp data/schedule.example.json data/schedule.json

# 5. 构建 + 预览
npm run build
npm run serve
```

产物长这样：

```
site/dist/
├── index.html        课表网页（数据已内联，断网也能看）
├── calendar.ics      日历订阅文件
├── schedule.json     给小程序远程拉取的数据
├── manifest.json     PWA 清单，支持「添加到手机桌面」
└── icon-*.png        图标（没放自己的就自动生成占位图）

miniprogram/
├── data/schedule.js  内置兜底数据（自动生成）
├── config.js         小程序配置（自动生成）
└── theme.wxss        主题配色（自动生成）
```

## 三、怎么导入你自己的课表

### 数据流

```
data/schedule.json   ← 唯一数据源。人和 Agent 都只改这一个文件
        │
        └── npm run build
                ├── site/dist/index.html            课表网页
                ├── site/dist/calendar.ics          日历订阅
                ├── site/dist/schedule.json         小程序远程数据
                └── miniprogram/data/schedule.js    小程序内置兜底数据
```

**永远不要手工编辑生成产物。** 下次 build 会把你的改动全部覆盖掉。

### 三种导入方式

**方式一：交给 Agent(推荐)**

把课表原件放进仓库，让 Agent 读 [`AGENTS.md`](AGENTS.md) 然后干活。话术见下一节。

**方式二：照着示例改**

`data/schedule.example.json` 里每种字段都有用法演示，包括单日、跨多日、全天事件、外部链接。照着改最直观。

**方式三：自己写脚本**

数据契约在 [`schema/schedule.schema.json`](schema/schedule.schema.json)，是标准 JSON Schema，可以直接喂给校验库或者代码生成工具。

### 导入完必须做的一步

```bash
npm run validate
```

它会检查：

- 必填字段有没有缺
- `cat` 引用的分类在 `CATS` 里有没有定义
- 日期格式对不对、`end` 是不是早于 `start`
- 时间段能不能解析
- **同一天里有没有时间重叠的课**
- 有没有课漏了教室
- 链接是不是绝对地址（相对路径在小程序和日历里都点不开）
- 配置里 `baseUrl` 是不是 https、CalDAV 有没有把密码往公开页面上放

有 ❌ 就会中止构建，⚠️ 只提示不拦截。

## 四、怎么给你的 Agent 下指令

仓库里有一份 [`AGENTS.md`](AGENTS.md)，是**写给 Agent 看的**，不是写给人看的。里面有数据契约、构建命令、校验规则、常见错误、以及明确的「不要做什么」。

### 第一次导入，直接复制这段

```
读一下这个仓库的 AGENTS.md。

我的课表原件在 ./我的课表.pdf，学院是【学院名】，班级是【班级名】，
学期从【开始日期】到【结束日期】，网页会部署在 https://【你的域名】。

请：
1. 把 config.example.json 复制成 config.json 并按上面的信息填好
2. 把课表提取成 data/schedule.json
3. 跑 npm run build
4. 把校验输出、以及所有你从原件里读不确定的条目，列成表格给我确认

不要跳过第 4 步。时间和教室你读错了我是看不出来的，必须让我逐条核对。
```

### 日常改课，复制这段

```
【9 月 12 日的公司财务教室从 A101 改到 B203，时间不变】

请改 data/schedule.json，在 CHANGELOG 里补一条记录，然后跑 npm run build,
把校验结果告诉我。改完只报告你改了哪几行，不要贴整个文件。
```

### 几个让 Agent 少犯错的提醒

- **明确说「不要手改生成产物」**。Agent 有时会图快直接去改 `site/dist/index.html`，改完下次 build 就没了。
- **让它先列不确定的条目再动手**，不要让它自己猜。PDF 里的时间和教室最容易读错。
- **每次收尾都让它跑 `npm run build`**，不要只改 JSON 就说完事了。

## 五、日常怎么自助更新

### 改课表（最常见）

```bash
# 1. 改 data/schedule.json
# 2. 重新构建
npm run build
# 3. 把 site/dist/ 传到你的托管上
```

**小程序端不用动**，它会自动拉到新的 `schedule.json`。只有改页面结构、样式、逻辑才需要重新提审。

### 建议同时做的两件事

1. **在 `CHANGELOG` 里补一条**。网页上有个「更新」标签页会显示它，同学能看到哪天改了什么，少很多重复提问。
2. **更新 `version` 和 `lastUpdated`**。小程序靠 `version` 判断远程数据有没有变，不改的话客户端不会刷新。

### 用 git 管起来

数据文件默认在 `.gitignore` 里（避免有人不小心把真实课表推到公开仓库）。想用 git 管自己的课表：

```bash
# 建一个私有仓库存你自己的数据和配置
git init
git remote add origin git@github.com：你/你的私有仓库.git
# 然后把 .gitignore 里 config.json 和 data/schedule.json 两行删掉
```

**确认仓库是私有的再删。**

## 七、数据契约

完整定义见 [`schema/schedule.schema.json`](schema/schedule.schema.json)。核心结构：

```jsonc
{
  "version": "2026-09-10 10:45",     // 小程序靠它判断有没有更新，每次改数据都要改
  "lastUpdated": "2026-09-10 10:45", // 页面上显示的文案

  "CATS": {                          // 事件分类，决定颜色和图例
    "required": { "label": "必修课程", "color": "#8c1d2b" }
  },

  "DAYS": [                          // 按时间正序排的日期块
    {
      "key": "0902",                 // 唯一短标识
      "start": "2026-09-02",
      "end": "2026-09-02",           // start 和 end 不同就是连续多天合并成一块
      "d1": "09.02", "d2": "周三",    // 标签上下两行
      "big": "9 月 2 日", "week": "周三",
      "events": [
        {
          "time": "09:00–12:30",     // 也支持 "全天"
          "cat": "required",         // 必须是 CATS 里定义过的 key
          "title": "决策分析与博弈论",
          "who": "李四",              // 多位老师用「、」分隔
          "where": "教学楼 A101",
          "nature": "必修", "credit": "2",
          "link": { "label": "课前阅读", "url": "https://..." }  // 必须是绝对地址
        }
      ]
    }
  ],

  "TEACHERS": {},   // 可选，老师简介弹窗。涉及个人信息，默认关闭
  "QA_ITEMS": [],   // 可选，常见问题卡片
  "CHANGELOG": []   // 可选，更新记录
}
```

页面模块可以在 `config.json` 的 `features` 里逐个开关，关掉的模块不渲染，对应数据留空即可。

## 八、隐私与合规

这套东西是给同学用的，不是对外发布的产品。有几条建议认真对待：

- **不要把学生名单、人数、联系方式放进数据文件。** 网页是公开的。
- **老师简介和照片涉及个人信息。** `features.teacherProfiles` 默认关闭。要开的话，内容请用学校官网的公开信息，并注明来源。
- **不要把课件、讲义、录音放进仓库或公开网页。** 这些通常有版权，而且不是你的。框架只支持存一个**外部链接**，不托管任何课程材料。
- **CalDAV 密码等于公开发布。** 见第 3 节。
- **页面上留一句免责声明。** 默认文案是「本页为非官方整理版本，一切安排以学校 / 学院正式通知为准」，建议保留。
